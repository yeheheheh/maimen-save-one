授权、隔离与常见报错
  • 不绑定能用吗：可以。未绑定时使用我方 MCP 的真实菜单与核价做体验，但下单会被拦截，避免用他人账号消费。
  • 去哪拿 Token：麦当劳 MCP 开放平台 open.mcd.cn/mcp，登录后在应用/密钥页面生成。
  • 授权失败 / 401：Token 复制不完整或已失效，重新生成后再绑定；失败不会覆盖原有绑定。
  • 读取账号失败：连接通了但取不到身份，通常是权限范围不足，请在开放平台确认已开通账号读取权限。
  • Token 失效：页面会标记「授权已失效」，重新绑定即可；失效期间不会重试下单。
  • 订单提交失败：价格变化会中止并请你重新确认；超时不会盲目重试，可在「这一单」里刷新状态或对账。
  • 数据隔离：报价、订单、提醒、固定套餐都按浏览器身份归属，A 看不到 B 的任何记录。

数据与边界

这页到底怎么算

演示模式：菜单、价格、券和积分均为示例数据，用于展示完整交互；不会读取账号，也不会下单。

实时模式：服务端配置麦当劳 MCP Token 后，会查询真实门店、菜单和门店券，并用官方 calculate-price 核价；Token 不会下发到浏览器。

价格口径：页面优先展示整单实付，包含配送费、包装费、券和积分抵扣；最终以麦当劳官方结算页为准。

执行模式：演示模式可以模拟领券、创建待支付订单、取消和模拟支付，不会写入真实账户；实时写操作只在单用户私有模式解锁后开启，并受金额、频次和 kill switch 限制。

省单管家：算完之后，管家会自动备单、领券、续报价、轮询订单并做重复单对账；每项自动化都能在管家中心单独关闭，实时模式下的写操作仍受解锁与限额约束。

安全边界：不自动支付，支付仍在麦当劳官方渠道完成；已支付订单不自动取消或退款，请走官方客服。
