演示数据

Token 只提交到本机服务端；校验通过才落盘，且不会回显到页面或接口。

  1. 拿到 Token 在麦当劳 MCP 控制台生成，是一串不含空格的长字符。
  2. 保存并校验 服务端立即连接 MCP 并试调一个只读工具，通过后才切换到实时数据。
  3. 重新算一单 状态变绿后点「一键算最省」，金额以官方 calculate-price 为准。
常见问题与报错
  • 401 / 校验未通过：Token 复制不完整或已失效，重新生成后再试。
  • 连接超时：服务端访问不了 mcp.mcd.cn，检查网络、防火墙或代理。
  • 能算价但不能下单：实时写操作需要服务端开启单用户私有模式并解锁，这是刻意保留的安全边界。
  • 重启后还要再填吗：不用。Token 保存在 data/live-token.json；若同时配置了环境变量，环境变量优先。
  • 想彻底关掉这个入口：启动时设 DISABLE_LIVE_SETUP=true。

数据与边界

这页到底怎么算

演示模式：菜单、价格、券和积分均为示例数据，用于展示完整交互；不会读取账号，也不会下单。

实时模式：服务端配置麦当劳 MCP Token 后，会查询真实门店、菜单和门店券，并用官方 calculate-price 核价；Token 不会下发到浏览器。

价格口径：页面优先展示整单实付，包含配送费、包装费、券和积分抵扣；最终以麦当劳官方结算页为准。

执行模式：演示模式可以模拟领券、创建待支付订单、取消和模拟支付，不会写入真实账户；实时写操作只在单用户私有模式解锁后开启，并受金额、频次和 kill switch 限制。

省单管家：算完之后，管家会自动备单、领券、续报价、轮询订单并做重复单对账；每项自动化都能在管家中心单独关闭，实时模式下的写操作仍受解锁与限额约束。

安全边界：不自动支付，支付仍在麦当劳官方渠道完成；已支付订单不自动取消或退款，请走官方客服。
